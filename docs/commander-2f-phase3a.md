Every Commander therefore remains outside every library even when destruction changes the availability of a printed draw static. Existing draw handling uses stored controllers and printed statics; this correction does not add effective-control or new draw-replacement semantics. ## Decisions, ownership, and final movement

The operation owns exact original subjects, source zone, movement kind, owner, effective affected controller, instruction controller, initial/current destination, placement, consumed ordinary occurrences, Commander proposal revision, and ordered semantic decision records. A concrete action carries a private checked operation window and current history stage so replay cannot answer a later revision or a later operation touching the same incarnation.

Ordering uses the affected object's effective controller on the Battlefield, with owner fallback for the admitted uncontrolled origins. Selecting the Commander candidate opens a separate owner-controlled boolean answer. The instruction controller never substitutes for either chooser. Self replacements retain 616.1a precedence. After each selection or answer, applicability is recomputed from the current proposal. Ordinary occurrences are consumed once per movement lineage. A Commander decline suppresses the opportunity only for that proposal revision; both decline/reconsideration and actual repeated acceptance work under 903.9b.

All simultaneous subjects remain in the pre-event state until every required replacement and private library-order choice is complete. Outstanding choices use APNAP, including restart when a nonactive player's selection creates an earlier owner's choice. Only the final destinations enter the transition kernel. Proposals and history never allocate an event group, increment generation, create an arrival opportunity, emit transition events, or queue arrival triggers.

Multiple cards going to one represented Top or Bottom position use incremental private owner ordering. Redirected-away movers do not enter the group. The selected order is committed with the complete simultaneous event. Shuffle obligations are owned instruction consequences and survive redirecting every intended mover or a named subject becoming impossible after a completed earlier instruction (701.24c). Production randomness remains `thread_rng`; deterministic shuffle regressions use the same completion function with seeded `StdRng`.

## Admission and failures

Structural admission examines the entire instruction envelope before executing its prefix and, for stack resolution, before popping the resolving entry. Conditional, modal, loop, nested `Multiple`, incompatible recipients, unsupported replacement actions/source combinations, and unsupported source-zone paths reject at that boundary.

Reached subjects are selected from the state produced by earlier completed instructions. A later leaf cannot rebind a target to a newer incarnation. Genuine now-impossible targets after a completed prefix are omitted while represented coupled obligations are retained. Each reached operation preflights its complete movement; final commitment prepares the full batch, continuous refresh, linked departures, generations, event-group allocation, and placement work before mutation.

Invalid, stale, wrong-player, or replayed answers preserve the pending operation and every prior valid record. A capacity failure while answering preserves that same state and history. An earlier completed prefix is retained. A failed reached preparation retains ownership of its resolving stack entry and the existing failure classification; the stopped state cannot replay that prefix through actions or restoration. There is no general whole-spell rollback or resumable failed-frame promise.

Ordinary same-zone results in admitted zones are no movement: the Graveyard→Hand→Graveyard control has no generation/event/group change. Exile→Exile (400.8) is rejected through complete source/catalog admission, before offers; Command origins are not admitted, so 400.10 is not claimed. Ordinary Library and generic Hand origins, including the future Library→Hand→Command→Library source-zone case, remain excluded with Phase 3B; only the closed captured Chittering Hand instruction is admitted. The reachable Battlefield proposal chain Library→Hand→Command→Library followed by decline completes with exactly one actual Battlefield→Library move.
